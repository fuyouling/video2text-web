# 01 · 背景与目标

> 模块定位：说明为什么要做 `video2text-web`、要达到什么目标，以及已经敲定的关键决策与依据。
> 上级索引：[00-overview.md](./00-overview.md)

## 1.1 背景

`video2text` 是一款基于 faster-whisper 的**本地音视频转写与总结工具**，支持 Windows，具备 GPU 加速、在线模型接入、API Key 管理、智能总结等能力。

现状与缺口：

- 目前仅有**桌面 GUI 与 Release 分发**，没有对外的展示窗口。
- 缺少**获客入口**（下载引导、SEO 落地页）与**内容资产沉淀**（文档、博客、教程）。
- 后期规划 **Pro 增值付费（收款）**，需要后端能力（支付、License 校验、用户系统）支撑，但当前没有承载位置。

## 1.2 目标

新建独立官网项目 `video2text-web`，用于：

1. **对外展示**：产品能力、特性、使用场景与下载入口（提升海外获客与 SEO）。
2. **内容沉淀**：文档、博客、教程等可长期积累的内容资产。
3. **付费预留**：为后期 **Pro 增值付费（收款）** 预留 Python 后端能力（支付、License 校验、用户系统）。

## 1.3 关键决策

### 1.3.1 MoR（Merchant of Record）说明

- **定义**：支付平台（Paddle）作为法律上的"商户"，负责收款、开票、全球 VAT/税务合规。开发者无需自建 VAT 申报。
- **为何选 Paddle**：覆盖地区广、对独立开发者友好、内置防欺诈与税务合规，契合跨境桌面软件 Pro 授权场景。
- **影响**：退款、开票、税务均由 Paddle 处理，后端只需处理 Webhook 落库与 License 签发/失效。

### 1.3.2 域名说明与风险

- `video2text.dpdns.org` 由 Cloudflare 托管，自带 SSL 且无需 ICP 备案，作为**唯一生产域名**。
- 国内站点（如需）后期单独规划域名与备案，**不复用当前托管**，避免备案与海外流量相互牵制。
- **已知风险与缓解**：`dpdns.org` 为免费动态 DNS 子域，已接受以下缓解：
  - 专业度：通过产品力、文案与 SEO 建立信任，不依赖域名后缀；
  - 归属权：尽量使用稳定服务商；若回收则迁移（见下方 MoR 风险）；
  - 邮件送达率：使用 Cloudflare Email Routing 或事务邮件服务商自建域名 DNS 配置，改善 SPF/DKIM/DMARC；
  - MoR 审核：部分 MoR（Paddle）可能拒绝免费子域；若入驻受阻，切换备选 MoR（Lemon Squeezy / Creem / Polar）或改用邮件交付 + 人工收款过渡。
- **结论**：不购买独立域名，`video2text.dpdns.org` 作为长期生产域名；相关风险在 [10 §10.4](./10-risks.md)、[11 §11.1](./11-tbd.md) 持续跟踪。

### 1.3.3 开源与 Pro 授权的关系

- 官网文案使用"open source / 开源"作信任背书前，需先确认 `video2text` 桌面端是否真正开源、以何种许可证发布。
- 若桌面端为开源，则**所有 Pro 权益必须由"本地无法轻易伪造的能力"构成**（见 [02 §2.3](./02-product-positioning.md) 与 [08 §8.7](./08-license-design.md)），否则客户端授权可被绕过；纯"功能开关"类权益在开源下形同虚设。
- 若桌面端为闭源，则 Pro 授权可依赖客户端逻辑，但需在隐私政策中明确"本地离线"边界。

## 1.4 范围边界

- **做**：静态官网（展示、下载、文档、博客）、SEO/OG、i18n、后期 Pro 收款与 License。
- **不做**：在线转写 SaaS、云端存储用户音视频、国内备案站点（本期）。
- **解耦原则**：前端静态、可纯静态托管；后端独立可部署；敏感逻辑（密钥、支付验签、License）只在后端。
